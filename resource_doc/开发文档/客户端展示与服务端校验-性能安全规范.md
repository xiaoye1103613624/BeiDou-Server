# 客户端展示 vs 服务端校验 — 性能与安全规范

> 戳记：`CLIENT_DISPLAY_VS_SERVER_AUTH_20260803`  
> 适用：北斗 GMS v083（`BeiDou-Server_xy` + `BeiDou-ijl15`）  
> 宗旨：**优化性能、提升服务端并发**；关键节点做数据处理与验证；**不做过多展示类请求**（浪费资源 + 伤体验）。  
> 服务端职责：**数据同步 + 校验为主**；更多展示能力下放客户端。

---

## 1. 原则表

| 维度 | 谁负责 | 允许行为 | 禁止行为 |
|------|--------|----------|----------|
| **展示** | 客户端本地画 / 本地缓存 | 悬停 tip、套装 tip、成长 tip 用已同步摘要或本地 WZ 渲染 | 悬停每次拉全量属性；无缓存重复查询；为 tip 新开高频 opcode |
| **同步** | 服务端在**关键时间点**推送或随装备包带摘要 | 穿戴、升级、强化成功、登录、进频、交易结算后同步 | 把「同步」伪装成每个 hover 的全量请求 |
| **校验** | 服务端权威 | 意图包 → 服务端计算结果 → 回写库存；抽查伤害/经济 | 信任客户端申报「我获得了 X」「我造成了 Y 伤害」 |
| **反作弊** | 服务端限频 + 审计 + 熔断 | cooldown/日限、异常日志、踢线/锁交易、证据保留 | 给展示 tip 加请求当反作弊；空喊口号不落库存事务 |

**一句话**：展示少请求、经济严校验；无关展示可放开，恶性玩家收紧。

---

## 2. 允许的服务端触发点（属性/摘要同步）

以下时间点**可以**（应优先）做属性摘要推送或随已有装备变更包带字段：

| 触发点 | 说明 |
|--------|------|
| 登录 / 选角进图 | 已穿装备成长/套装摘要一次性或随 inventory 下发 |
| 穿戴 / 卸下 | 装备变更包可附带成长等级、强化星、套装件数摘要 |
| 升级 / 升级装备 itemLevel | 变更后推送或使客户端缓存失效后单次拉取 |
| 强化成功 / 砸卷 / 潜能变更 | 同上 |
| 交易 / 仓库 / 商店结算 | 经济事务完成后同步库存，**不是** tip 请求 |
| 换频 / 重连 | 抽查异常数量、负数、槽位重叠 |

**默认不触发**：单纯鼠标悬停、打开装备栏浏览、对比 tip 重绘。

---

## 3. 禁止清单（展示与网络）

1. **悬停 tip 高频拉全量属性**（如成长 tip 默认每帧/每次 `OnEquipTipDrawn` 无节流打 `0x17D`）。
2. **重复展示查询无缓存**：同 `itemId`（及关键指纹：enhance/itemLevel/scroll）短时间内重复 build。
3. **超时狂重试**：pending 超时后无限重发；应退避 + 次数上限，有本地数据先画。
4. **为反作弊给每个 tip 加请求**。
5. **客户端「领取结果包」直改进包**（伪造获得道具）。
6. 客户端改 `.img` 用 `robocopy`/`Copy-Item` 当恢复（须走 **orange-wz / wzimg MCP**，见 WZ 规范）。

## 4. 成长 tip / 套装 tip — 目标架构

### 4.1 目标

| 项 | 目标 |
|----|------|
| 渲染 | **客户端本地画**（套装 tip 已基本本地；成长 tip 逐步本地化） |
| 数据 | 变更时**推送**或装备包**带摘要**；悬停 **零请求或极少请求** |
| 缓存 | 客户端正缓存（有文案）跨 hide/show 保留；负缓存（确认无成长）可在 hide 时失效以便升级后刷新 |
| 服务端 | build 结果按「角色+装备指纹」短缓存；热路径日志降级为 debug |

### 4.2 现状与改动量（评估）

| 模块 | 现状 | 改为「变更推送/本地展示」改动量 | 立刻可做 |
|------|------|----------------------------------|----------|
| 成长 tip `0x17D` / `EquipGrowthTip*` | 悬停按需拉；有 pending/本地 fallback | 中：需在强化/升级路径挂推送 + 客户端消费推送包；协议可增量 | 取消无意义超时狂重试；有本地先画；同装备短缓存；服务端 build 短缓存 |
| 套装 tip `setitem` | **已本地绘制**，无悬停经济包 | 低：继续保持；摘要随穿戴同步即可 | 勿新增悬停请求 |
| 自定义封包悬停 | 易滥用 | — | 新展示功能默认本地；确需服务端数据则走变更推送 |

**协议**：最小优化**不爆改**；不碰 `UIWindow.img`。

### 4.3 与 WZ / 改端衔接

客户端展示素材与 String 仍按改端流程走 **orange-wz MCP / wzimg MCP**；本规范只管「何时请求服务端」，不替代 WZ 写入纪律。

## 5. 伤害：抽查校验 + 恶性限制

| 层级 | 策略 |
|------|------|
| 无影响展示 | 飘字、简易伤害数字等可下放客户端 |
| 常规战斗 | **抽查校验**（抽样比对期望伤害区间 / 技能 CD / 命中合法性） |
| 恶性玩家 | 提高抽查率；超阈踢线、锁技能、记黑名单 |
| 禁止 | 每个 hit 全量服务端重算展示用细节（除非玩法强依赖） |

## 6. 专章：资源获取 / 消耗限制

### 6.1 原则

**加减道具、金币、点券、材料，只信服务端库存与事务。**  
客户端可发「意图」（点领取、确认分解），**不得**发「结果」（我获得了 itemId×N）。

### 6.2 可落地方案

| 手段 | 落点（北斗栈） | 做法 |
|------|----------------|------|
| 权威入口 | `InventoryManipulator` / `ModifyInventory` / 脚本 `gainItem` | 所有给物/扣物最终进 manipulator；脚本禁止旁路直接改 DB 行后只发包 |
| 限频 | 领奖、分解、合成、商店、脚本给物 | 同角色/账号：`cooldown`（毫秒级防连点）+ **日限/周限**（配置表或 DB 计数） |
| 事务 | 合成/交换/交易 | 先校验空间与材料 → 扣材料 → 加产出 → 失败整单回滚；`checkSpace` 通过后再改库存 |
| 产出审计 | 日志 + 监控 | 短时间大量 `gainItem`/金币 → 记审计日志；可熔断：踢下线 / 锁交易 / 暂时关闭该脚本入口 |
| 展示隔离 | tip / UI | **不要**用 tip 请求做资源校验 |

### 6.3 脚本与领奖

1. `gainItem` / `gainMeso` / 点券接口：统一校验层（角色状态、任务阶段、背包空间、日限）。
2. 禁止：客户端收到「假成功包」自改本地库存后指望下次登录以客户端为准（登录以 DB/服务端为准）。
3. NPC/任务领奖：服务端记录「已领」标记（quest/exinfo/独立表），重复意图包幂等返回已领。

## 7. 专章：防伪造发包 / 防复制道具

### 7.1 核心原则

| # | 原则 |
|---|------|
| 1 | **永不信任客户端申报的「获得了什么」**；只接受意图，结果由服务端算 |
| 2 | **经济类包必须服务端权威**；展示类包可下放（与 §1 衔接） |
| 3 | 装备/道具变更用 **服务端库存事实 + 唯一 serial/inventoryitemid + 事务**；移动/交换做 **幂等与状态机** |
| 4 | 复制成功迹象 → **回滚 + 封禁标记 + 保留证据日志** |

### 7.2 可落地方案（按攻击面）

#### A. 意图 vs 结果

- 允许：`使用卷轴`、`点击 NPC 选项`、`交任务`、`拖拽移物（from/to 槽）`。
- 拒绝：客户端自定义包声称 `addItem(id, qty)`、`setQuantity`、`cloneEquip`。
- Handler 内：读意图字段 → 服务端查库存/WZ/脚本 → 调用 `InventoryManipulator` → 用 `PacketCreator.modifyInventory` **单向通知**客户端。

#### B. 移物 / 交换 / 复制类包

1. **from/to 槽位校验**：源槽存在、数量足够、目标类型合法、现金/普通栏不串。
2. **状态机**：`Idle → Moving → Applied`；同一角色同时只允许一个进行中的库存操作锁（或按 inventory 分段锁）。
3. **幂等**：同一操作带服务端下发的 `actionId` / 或依赖「操作后源槽已空」——重放包因源空而失败，不得再加一份。
4. **唯一 serial**：装备实例以 DB `inventoryitemid` / 等价唯一键为准；禁止客户端自造 id。
5. **合并堆叠**：仅允许同 itemId、同属性可堆叠规则下合并；不可堆叠装备禁止 quantity>1 的「复制合并」。

#### C. 封包校验

| 检查 | 说明 |
|------|------|
| 长度 / 可读性 | 读超包、短包直接丢弃 |
| 字段范围 | itemId、qty、slot 在合法区间；禁止负数数量进入给物路径 |
| 操作时序 | 未打开 NPC / 无会话却交任务、未在商店却买物 → 拒 |
| 重放 | 短时重复同包：时间窗去重、或「进行中操作锁」 |
| 换频/登录抽查 | 异常数量、负数、同 serial 多槽、槽位重叠 → 校正或踢线并打日志 |

#### D. 与现有类衔接

| 组件 | 职责 |
|------|------|
| `InventoryManipulator` | 唯一推荐的加减/移动实现；新玩法不要复制一套直接改 `Item` 再发包 |
| `ModifyInventory` + `PacketCreator.modifyInventory` | **服务端→客户端**同步，不是客户端上报结果的入口 |
| 脚本 `gainItem` 等 | 必须走校验（空间、任务态、日限）；大额给物记审计 |
| 成长/套装 tip | **不参与**经济校验；按 §4 减少请求 |

#### E. 恶性处置流程（可执行）

1. 检测：同 serial 双持、移物后源仍在且目标多一份、短时重复 gain 超阈。  
2. 立即：回滚到操作前快照或踢线拒绝存档脏数据。  
3. 标记：账号/角色封禁或交易锁标志。  
4. 证据：保留原始包 hex、角色 id、时间、前后库存摘要到审计日志（勿只打 info 一句）。

---

## 8. 性能与安全的衔接口诀

```
展示 → 本地 / 变更推送 / 短缓存 / 悬停零或少请求
经济 → 意图包 + 服务端事务 + 限频日限 + 审计熔断
伤害 → 抽查 + 恶性加严
反作弊 → 绝不靠 tip 请求堆出来
```

## 9. 后续可选优化清单

1. 成长 tip：**变更推送模型**（强化/升级成功带摘要，废弃悬停默认 `0x17D`）。  
2. 伤害抽查框架：可配置抽样率与恶性阈值。  
3. 资源日限配置中心：领奖/脚本统一中间件。  
4. 库存操作锁 + 移物幂等 token。  
5. 登录/换频库存一致性扫描（serial 冲突、负数量）。
