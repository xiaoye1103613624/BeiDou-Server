## 1. 项目概览

### 1.1 项目简介

北斗服务器（BeiDou Server）是一套基于 **OdinMS** 开源框架二次开发的 **冒险岛（MapleStory）** 私有服务器，服务端版本对应 **GMS v83**。项目在 OdinMS 基础上进行了大量现代化改造，引入 **Spring Boot 3.2 + JDK 21** 生态，并新增了完整的 **Web 管理后台**、装备强化/进阶系统、国际化支持、系统救援等特色功能。

### 1.2 技术栈

| 层次 | 技术 | 版本 | 用途 |
|------|------|------|------|

| **框架** | Spring Boot | 3.2.3 | IoC 容器 + REST API |
| **安全** | Spring Security + JWT | 3.2.3 / jjwt 0.9.1 | 认证与授权 |
| **网络** | Netty | 4.1.109 | 游戏客户端 TCP 通信 |

### 1.4 启动方式

```bash
# IDE 中直接运行 ServerApplication.main()
# 或命令行启动
java -jar BeiDou.jar --spring.config.location=application.yml
```

**启动流程：**

1. `ServerApplication.main()` 被调用
2. `initDb()` 解析 YML 配置，自动创建数据库（如不存在）
3. `SpringApplication.run()` 启动 Spring Boot 容器
4. `ServerConfig` 的 `CommandLineRunner` 执行游戏服务初始化：
   - 加载 WZ 游戏数据（地图/怪物/技能/NPC等）
   - 初始化世界（World）和频道（Channel）
   - 启动 Netty 登录服务器（`LoginServer`）和频道服务器（`ChannelServer`）
   - 启动定时任务（`TimerManager`）

### 1.5 端口说明

| 端口 | 用途 |
|------|------|
| `8484` | 游戏客户端登录端口（Netty TCP） |
| `7575~7575+N` | 频道服务器端口（每个频道一个独立端口） |
| `8686` | Web 管理后台端口（Spring Boot Undertow HTTP） |

### 2.2 关键设计模式

| 模式 | 应用场景 | 示例 |
|------|----------|------|
| **单例模式** | 全局唯一的管理器 | `Server.getInstance()`, `TimerManager.getInstance()` |
| **工厂模式** | 创建复杂对象 | `MapFactory`, `PortalFactory`, `ReactorFactory`, `SkillFactory` |
| **策略模式** | GM 命令/封包处理/移动类型 | `Command` 接口, `PacketHandler` 接口, `LifeMovement` 体系 |
| **观察者模式** | 地图对象变化通知 | `MapObject` + `AbstractCharacterListener` |
| **模板方法** | 封包处理器/移动处理器 | `AbstractMovementPacketHandler`, `AbstractDealDamageHandler` |
| **建造者模式** | 封包构造 | `Packet` 内部 `ByteBufOutPacket` |
| **装饰器模式** | WZ 数据提供者封装 | `DataProviderFactory` + `DataTool` 系列 |
| **代理模式** | 延迟加载 | `DoorObject` 代理 `Door` |

### 2.3 并发模型

| 组件 | 并发策略 | 实现 |
|------|----------|------|
| **全局服务** | `ReentrantLock` / `ReentrantReadWriteLock` | `Server` 中的 `srvLock`, `wldRLock/wldWLock`, `lgnRLock/lgnWLock` |
| **地图实例** | 逐地图独立锁 | `MapleMap.mapLock` |
| **玩家存储** | `ReentrantReadWriteLock` | `PlayerStorage` 读写分离 |
| **定时任务** | `ScheduledThreadPoolExecutor` + JMX 监控 | `TimerManager` |
| **IO 线程** | Netty `EventLoopGroup` (boss + worker) | `ChannelServer`, `LoginServer` |
| **虚拟线程** | JDK 21 `Virtual Threads` | `ThreadManager` 封包处理器执行 |

### 2.4 服务生命周期

```
启动：
  ServerApplication.main()
    └─ initDb()                          # 自动建库
    └─ SpringApplication.run()
        └─ ServerConfig.run()            # CommandLineRunner
            ├─ GameConfig.load()         # 加载游戏配置
            ├─ WZ 数据加载                # Map/NPC/Skill/Mob/Item 等
            ├─ World/Channel 初始化       # 创建世界和频道实例
            ├─ LoginServer.start()       # 启动 Netty 登录服务器
            ├─ ChannelServer.start() x N  # 启动 N 个 Netty 频道服务器
            └─ TimerManager.start()      # 启动定时任务调度

运行：
  ┌─ 网络层：持续接收/解析/派发客户端封包
  ├─ 游戏层：处理战斗/移动/交互/交易等逻辑
  ├─ 脚本层：按需执行 GraalVM JS 脚本
  └─ Web 层：处理管理后台 HTTP 请求

关闭：
  Spring Boot Shutdown Hook
    ├─ Server.shutdown()
    ├─ Channel 逐一关闭并保存玩家数据
    ├─ TimerManager.stop()
    └─ Netty EventLoopGroup 优雅关闭
```

### 3.2 封包结构（GMS v83）

```
┌─────────┬──────────┬──────────────┬────────────┬──────────┐
│  4字节   │  2字节   │   可变长度     │   2字节    │          │
│  Header │  Length  │   Payload     │   Opcode   │  Data... │
│  (IV前4) │ (数据长度) │  (加密载荷)    │  (操作码)   │ (业务数据) │
└─────────┘└──────────┘└──────────────┘└────────────┘└──────────┘
```

**服务端内部封包接口：**

```java
// 输入封包（从客户端读取）
public interface InPacket {
    byte[] getBytes();
    int readByte();
    short readShort();
    int readInt();
    long readLong();
    Point readPos();
    String readMapleAsciiString();
}

// 输出封包（发往客户端）
public interface OutPacket {
    void writeByte(byte value);
    void writeShort(int value);
    void writeInt(int value);
    void writeLong(long value);
    void writePos(Point point);
    void writeMapleAsciiString(String s);
}
```

### 3.3 加密体系

**客户端 → 服务端（解密）：**

```
PacketDecoder (Netty Inbound Handler)
  ├─ MapleCustomEncryption.decryptData()    # 自定义解密（shuffle/head变换）
  ├─ MapleAESOFB.crypt()                    # AES-OFB 解密
  └─ ByteBufInPacket                        # 封装为可读封包
```

**服务端 → 客户端（加密）：**

```
PacketEncoder (Netty Outbound Handler)
  ├─ ByteBufOutPacket                       # 封包序列化
  ├─ MapleAESOFB.crypt()                    # AES-OFB 加密
  └─ MapleCustomEncryption.encryptData()    # 自定义加密（shuffle/head变换）
```

**关键类职责：**

| 类 | 职责 |
|-----|------|
| `MapleAESOFB` | AES-OFB 模式加解密（握手阶段协商 IV） |
| `MapleCustomEncryption` | 封包头变换（GMS v83 特有的魔术字节处理） |
| `InitializationVector` | 收发方向独立 IV 管理 |
| `PacketCodec` | 封包长度帧解码器（处理 TCP 粘包/拆包） |
| `PacketDecoder` | 解密 + 构建 `ByteBufInPacket` |
| `PacketEncoder` | `ByteBufOutPacket` + 加密 |
| `GMSV83PacketProtocol` | GMS v83 协议版本实现 |

### 3.4 操作码（Opcode）分发体系

```
1. 客户端发送封包 → 2字节 Opcode 标识操作类型
2. PacketProcessor.handlers[opcode] 获取对应 PacketHandler
3. handler.validateState(client) 校验客户端状态
4. handler.handlePacket(packet, client) 执行业务逻辑
```

```java
// 接收操作码（客户端 → 服务端）— 200+ 操作码
public enum RecvOpcode {
    LOGIN_PASSWORD, CHARLIST_REQUEST, CHAR_SELECT, PLAYER_LOGGEDIN,
    MOVE_PLAYER, CLOSE_RANGE_ATTACK, RANGED_ATTACK, MAGIC_ATTACK,
    TAKE_DAMAGE, NPC_TALK, ITEM_PICKUP, CHANGE_MAP, CHANGE_CHANNEL, ...
}

// 发送操作码（服务端 → 客户端）— 200+ 操作码
public enum SendOpcode {
    LOGIN_STATUS, CHARLIST, WARP_TO_MAP, SPAWN_PLAYER,
    REMOVE_PLAYER, NPC_TALK, SHOW_STATUS_INFO, UPDATE_STATS, ...
}

// Handler 注册示例
handlers[RecvOpcode.LOGIN_PASSWORD.getValue()] = new LoginPasswordHandler();
handlers[RecvOpcode.CHAR_SELECT.getValue()] = new CharSelectedHandler();
handlers[RecvOpcode.MOVE_PLAYER.getValue()] = new MovePlayerHandler();
handlers[RecvOpcode.NPC_TALK.getValue()] = new NPCTalkHandler();
```

### 3.5 双服务器设计

**LoginServer（登录服务器，端口 8484）：**
- 职责：账号认证、角色列表、角色创建/删除、频道选择
- Handler：`org.gms.net.server.handlers.login.*`

**ChannelServer（频道服务器，端口 7575 起递增）：**
- 职责：游戏内所有操作（移动、战斗、交易、聊天等）
- Handler：`org.gms.net.server.channel.handlers.*`
- 每个 World 的每个 Channel 独立启动一个 Netty Server

**频道切换流程：**

```
1. 客户端 → LoginServer: 选择世界+频道
2. LoginServer → 客户端: 返回频道的 IP:Port
3. 客户端断开 LoginServer 连接
4. 客户端 → ChannelServer: 建立新 TCP 连接
5. ChannelServer: PlayerLoggedinHandler 加载角色数据
6. 角色进入游戏（WARP_TO_MAP → SPAWN_* 系列封包）
```

// 解决 GraalVM JS 中 short 溢出导致负属性使客户端闪退的问题
public static short safeAddStat(short current, int add) {

    return (short) result;

#### 9.4.2 数据库注释强制要求

**所有新建的表和字段必须包含中文 COMMENT：**

```sql
-- ✅ 正确示例
CREATE TABLE IF NOT EXISTS `xy_level_reward`
(
    `id`          BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    `level`       INT    NOT NULL COMMENT '要求等级',
    `meso`        INT    DEFAULT 0 COMMENT '金币奖励',
    `enabled`     INT    DEFAULT 1 COMMENT '是否启用（0=禁用 1=启用）',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='等级奖励配置表';
```

**注释编写规范：**

| 规则 | 说明 |
|------|------|
| 语言 | 使用简洁中文 |
| 表注释 | `COMMENT='表的中文描述'`，说明表的业务用途 |
| 字段注释 | `COMMENT '字段的中文描述'`，说明字段含义 |
| 枚举字段 | 需注明各值含义，如 `COMMENT '职业群（warrior/archer/mage/thief/pirate）'` |
| 布尔字段 | 需注明真/假含义，如 `COMMENT '是否启用（0=禁用 1=启用）'` |
| 外键字段 | 注明关联关系，如 `COMMENT '关联 xy_equip_enhance_config.id'` |
| ALTER TABLE | 新加字段同样强制加 COMMENT |

**禁止行为：**
- ❌ 不写 COMMENT
- ❌ 注释写英文或重复字段名
- ❌ 枚举字段不给值含义说明

### 10.7 常见问题
