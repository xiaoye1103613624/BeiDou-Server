# 第二坠悬停无 Tip / 红色不生效 — HitTest+BP23 冲突修复（20260726n）

## 现象

经典窄栏 remap 到 `(104,134)`（戳记 `PENDANT2_CLASSIC_XY_20260726m`）后：

- 第二坠图标能画出来（主项链右侧空「项链」格）
- 鼠标悬停：**无物品 Tip**
- 观感：图标带红底，像「不生效」

## 根因（客户端，非服务端）

1. **HitTest 循环不含 BP51**  
   `CUIEquip` 经典 HitTest（`0x00801200`）：
   - `cmp esi, 0x30` → BP>48 直接跳过矩形测试
   - 循环尾 `cmp edx, 0x32` → BP≥50 结束  
   因此 GetSlotXY/HitTest 表即使写了 `[50]=(104,134)`，悬停也永远测不到 BP51 → **无 Tip**。

2. **`(104,134)` 本是 GetSlotXY BP23**  
   原表：`GetSlotXY[22] BP23 = (104,134)`，而 `HitTest[22]=(46,44)`。  
   第二坠画在同一格上，叠了 BP23 空槽底图（偏红），看起来像「不生效」。  
   Align 武器 HitTest 后，该格又没有任何合法 HitTest → 仍无 Tip。

3. **`is_correct_bodypart` 不是主因**  
   原生 112 路径对 BP51 有 ZF trampoline（`cmp 0x33` 后 jmp 到 `jz`），本来就接受 17|51。  
   `shoulders.cpp` 钩子保留作显式保险。服务端 `-51` / `SET_EXTRA_PENDANT_SLOT` 正常。

## 修复（ijl15 `PENDANT2_HT_RED_20260726n`）

- 仍映射：`GetSlotXY[50]=HitTest[50]=BE27E0[51]=(104,134)`
- **腾空**：`GetSlotXY[22]` 改到其 HitTest `(46,44)`，避免与第二坠抢格
- **扩展 HitTest**：`0x30→0x33`、`0x32→0x33`，使 BP51 参与悬停
- 保留右栏 HitTest→GetSlotXY 对齐（武器悬停）与 `pendant2_ui` 进图后挂载
