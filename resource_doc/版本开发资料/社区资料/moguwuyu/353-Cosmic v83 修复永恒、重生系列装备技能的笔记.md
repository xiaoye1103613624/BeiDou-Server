根据官方数据，永恒装备和重生装备都是携带技能等级提升效果的。
wz 解析
以永恒玄妙帽1002777为例，打开Character.wz并找到1002777里的level节点，里面有两个子节点
case
和
info
。
level/info节点
这个节点用于存放升级数据，info下的数字节点代表着对应的道具等级。在客户端里道具的最高等级（显示Max）是取info下面的最高数字。
在等级节点下面，
exp 节点
为当前等级升级所需经验（如果达到最高等级则无效），除exp外就是
属性节点
了，每组属性都有Min和Max两个节点，表示升级后获得的属性值范围。
从后端代码可知，支持的属性有（自己添加，记得加上Min和Max）
incDEX
incSTR
incINT
incLUK
incMHP
incMMP
incPAD
incMAD
incPDD
incMDD
incACC
incEVA
incSpeed
incJump
需要注意的是exp里的值和获取的经验值不是1:1的关系
level/case节点
这个节点用于存放道具技能数据
case 下有两个节点
0
和
1
暂时理解
为0表示未获得，1表示获得。这两个节点下面都有一个 prop 值，用来计算概率：0下的prop为9，1下的prop为1，也就是说获得的概率为10%
然后看1节点下面还有一些数字节点，这些数字和道具等级是挂钩的，如果客户端判定你这个道具获得技能了，就会在这里找到当前道具等级对应的数字节点，然后在这个数字节点里面查找技能信息。
我们打开数字6节点，里面有一个hs属性和一个Skill节点，其中hs的值用于在String.wz中查找对应的文字，附加在装备最底部，也就是显示“xx技能+1”字样。Skill节点就是用来配置提升的技能。
Skill节点下面就是一个List了，每个节点下面都是id和level对应要提升的技能id和要提升的等级。
修复思路
首先，在确定了这是一个官方自带的功能后，初步判断就是客户端具备这个功能，不需要动到客户端。
结论一：客户端不需要修改
既然是客户端上有的功能，也就是说我只要强行让客户判断这个装备是带技能的就可以了，所以联想到服务端发送的封包，于是检查服务端创建装备信息的封包，但可惜的是封包的代码里没有技能相关的部分，所以这个封包代码肯定有问题（或者说不完善）。
结论二：需要修改封包方法。
既然083已经有这个功能了，于是我想着下载高版本的服务端源码来看看他们的封包代码。装备信息部分基本上是相同的，但是GMSv146的封包里比v83多了这么一段
outPacket.encodeByte(equip.getIncSkill() > 0 ? 1 : 0);
这段代码夹在item level和flag之间
，于是检查083的代码，发现代码写死成
p.writeByte(0);
把这个地方改成1，测试。
依然不显示技能（因为跟着cosmic的资源，我把永恒装备刷到30级去了），看到wz节点里那个数字节点6，加之在官方数据里，永恒装备最高也就6级，于是联想到这个可能有关联，遂在数据库把身上装备的等级改成6级，测试。
成功显示装备技能
。
至此，装备技能的大体思路已经出来了。装备升级的属性和技能其实全都是由服务端控制的。
装备获得并显示技能的流程大致如下
人物的某些行为（如获取经验）时，服务端检查装备是否存在等级节点
（存在）按比例将获取的经验增加到装备经验里（检查装备的exp节点会发现，这个节点的值非常低，所以不可能是1:1的经验值）
装备升级时，服务端检查装备的等级节点是否存在技能
（存在）计算prop概率，记录技能的获得情况 boolean
创建装备属性的封包时，将该属性发送给客户端
（属性为true时）客户端去装备的level节点（对应当前道具等级，必须是相同值）从中提取所有的技能数据
然后根据角色职业在装备属性里显示hs的文字，并在技能栏里显示+x（比如装备同时有火凤球、冰凤球时，火毒只显示火凤球，冰雷只显示冰凤球）
这里面Character.wz里的hs会指向到String.wz，所以具体显示的文字还是去String.wz设置的
后来我在高版本的wz中看了一些特殊的戒指数据后发现
p.writeByte(0)
和wz的关系：原来封包那一段不仅仅是true才显示技能，而是true显示case/1里的数据，false显示case/0里的数据
知道了如何控制客户端显示装备技能以后，剩下的就是服务端的实现了。
添加装备属性 skill 布尔值（这一步一定要小心，MTS等复制场景要补齐字段，不然会造成skill数据丢失）
p.writeByte的值根据equip.getSkill()的值传0和1
Character代码中添加一个Map用来存放临时技能等级。
添加更新装备技能（3中的Map）的方法updateEquipSkill，同时在equippedItem和unequippedItem方法中调用updateEquipSkill，这样能确保玩家登录的时候和穿/卸装备的时候会更新临时技能等级。
装备升级的地方添加代码，通过case里的值和升级后的道具等级，判断是否有技能可以获得，如果有的话，就按概率获得技能（修改装备的skill为true）。同时触发Charater的updateEquipSkill，确保装备获得技能后即刻生效。
在获取人物技能等级的地方（getSkillLevel）加上技能的临时等级，注意getSkillLevel有两处，都要修改。
这样永恒装备升级后就有10%的概率获得技能（skill，设置为true），同时更新临时技能等级到一个Map。服务端取玩家技能等级的时候附加上这个Map里的等级，
于是装备的技能提升就这么成了。
还有一种玩法
，根据高版本的戒指来看。在等级节点下面不添加任何东西来禁止通过经验升级。然后通过自定义脚本来提升装备等级，获得对应的技能。
要注意的一点
部分高版本的戒指技能数据是塞在level/case/0中的，虽然不知用意如何，我们只要让装备的skill为false就可以显示了。
我后来根据这个玩法改造了怪物戒指，就不需要再创建N个戒指来兑换了，直接给戒指升级就可以了。
由于 cosmic 采用了魔改的装备升级方法，所以想要完美还原原版的体验，还需要把魔改部分改回来。以下是参考修改，这个修改只是完善了装备技能，不包含获取属性的部分和装备升级的部分。
根据这个设计，是可以创造出玩家学习上限30，但是通过装备技能突破30级上限的设定。需要在Skill.wz中添加好对应的技能数据
实际技能的效果还是要在服务端进行校验和计算，如果你想添加特殊的技能效果也完全是可以的。
