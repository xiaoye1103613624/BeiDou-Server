# 冒险岛 WZ 文件格式与版本差异

> 资料整理日期：2026-06-17
> 来源：MapleLib（lastbattle，WZ/协议工具库）、HaRepacker-resurrected、HeavenMS / Cosmic README
> 用途：理解 WZ 数据文件的解析、编辑与跨版本差异，指导北斗的 WZ 资源处理

---

## 一、WZ 是什么

WZ 文件是冒险岛客户端和服务端共用的**资源/数据文件**，包含地图、物品、技能、UI、怪物、NPC 等所有游戏数据。

- **客户端**：直接读取 `.wz` 二进制文件（含贴图 sprite、音效等）。
- **服务端**：通常需要把 `.wz` 转成 **XML（.img.xml）** 格式再读取——服务端不需要贴图，只要数据节点。北斗的 `wz-zh-CN/` 目录存放的就是导出后的服务端 XML。

> 北斗启动时通过系统属性 `wz-path` 指向 WZ 目录；Cosmic 同理，jar 不打包 WZ。

---

## 二、核心工具：HaRepacker-resurrected

管理（查看/编辑/导出）`.wz` 文件的标准工具是 **HaRepacker-resurrected**（基于 MapleLib）：
- GitHub: https://github.com/lastbattle/Harepacker-resurrected
- 配套有 **HaCreator**（地图编辑器）。

### v83 WZ 编辑标准流程（HeavenMS/Cosmic/北斗 通用）
1. 用 HaRepacker（建议 4.2.x 版），加密方式选 **"GMS (old)"**。
2. 打开目标 `.wz`，在节点树（node hierarchy）中修改（注意：跨节点复制粘贴偶尔不稳定）。
3. 保存修改后的 `.wz`，**覆盖客户端目录**里的原文件。
4. **重新用 "Private Server" 导出选项**，把改动后的 XML 导出到服务端的 WZ.XML 目录，覆盖旧内容。

> ⚠️ **同步方向很重要**：始终"客户端 .wz → 服务端 XML"单向导出。
> 反向（服务端 XML → 客户端 .wz）的"server-to-client"导入**可能引发客户端 bug**，需格外谨慎；而"client-to-server"导入是安全的。

## 三、WZ 版本/加密差异（MapleLib 的 WzMapleVersion）

不同地区/版本的 WZ 加密方式不同，MapleLib 用 `WzMapleVersion` 枚举区分：

| 枚举值 | 含义 |
|--------|------|
| `GMS` | 国际服（较新） |
| `GMS (old)` | 国际服旧版（**v83 等 pre-BB 用这个**） |
| `EMS` | 欧服 |
| `BMS` | 巴西服 / 通用 |
| `CUSTOM` | 自定义密钥 |
| `GENERATE` | 需暴力破解密钥时使用（用 HaRepacker 的 brute-force 功能找密钥） |

**实践**：v83（北斗/HeavenMS/Cosmic）编辑时统一选 **GMS (old)**。

## 四、按版本时代的文件格式差异

### 1. Pre-Big Bang（v83 及更早）：有 List.wz
- 早期版本存在 **List.wz** 索引文件，需用专门的 ListEditor 处理。
- MapleLib 中通过 `WzTool.IsListFile(filePath)` 判断是否为 List 文件。
- 北斗是 v83，属于这一时代。

### 2. 普通 .wz 时代（大爆炸后到 ~v220）
- 仍是 `.wz` 二进制归档，无 List.wz。
- 支持 **Data.wz 热更文件** 和裸 `.img` 文件（MapleLib 用 `LoadDataWzHotfixFile` 加载）。

### 3. .ms 加密时代（约 v220+）
- 引入 **`.ms` 文件**：在 `.wz` 外面再包一层加密。
- MapleLib 用 `WzMsFile` 读取，再 `LoadAsWzFile()` 转回标准 WzFile。
- 高版本（如 v214 Moonlight）需自行从客户端 dump WZ：
  HaRepacker → Tools → Export File(s) To → **Private Server XML**。

> MapleLib 官方支持范围：**beta v1 → v260++**，覆盖几乎所有版本。

## 五、MapleLib 解析 WZ 的核心 API（参考其他语言实现思路）

> MapleLib 是 C# / .NET 库；北斗用 Java 自己的 `org.gms.provider.wz` 解析器，但概念一致，可对照理解。

WZ 数据是**树形结构**：`WzFile → WzDirectory → WzImage(.img) → WzImageProperty(节点)`。

关键概念：
- **WzFile**：一个 `.wz` 归档，`ParseWzFile()` 解析。
- **WzDirectory**：目录节点，可含子目录和 WzImage。
- **WzImage**：对应一个 `.img`（如 NPC.wz 下每个 NPC 是一个 `.img`），`ParseImage()` 后才能访问属性。
- **WzImageProperty**：叶子/分支节点，按路径访问用 `GetFromPath("folder/subfolder/property")`，分隔符是 `/`。
- 提取贴图：`WzCanvasProperty` → `GetLinkedWzCanvasBitmap()`。

> 对应北斗：`org.gms.provider`（通用接口 Data/DataProvider/DataEntity）+ `org.gms.provider.wz`（WZ 解析），以及 `ItemInformationProvider`、`SkillbookInformationProvider` 等数据提供者。

## 六、相关：NX 格式（替代 WZ 的方案）

部分模拟器（如 Edelstein v95）改用 **NX 文件格式**（nxformat.github.io）而非 WZ，读取性能更好。Valhalla 也参考了 NX。北斗用的是 WZ XML，不涉及 NX，但了解其存在有助于阅读其他源码。
