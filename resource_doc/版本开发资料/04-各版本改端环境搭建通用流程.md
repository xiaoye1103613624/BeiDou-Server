# 各版本冒险岛改端环境搭建通用流程

> 资料整理日期：2026-06-17
> 来源：Cosmic / HeavenMS / Destiny / Valhalla / Moonlight / TW113 README
> 用途：横向对比各版本/各语言服务端的搭建套路，提炼通用步骤，辅助北斗(v83)的部署理解

---

## 一、通用三件套：数据库 + 服务端 + 客户端

无论哪个版本，改端都要准备三样东西：
1. **数据库(Database)**：存账号、角色、背包等。绝大多数用 **MySQL 8+**。
2. **服务端(Server)**："大脑"，在客户端之间路由网络流量。
3. **客户端(Client)**：玩游戏的 `MapleStory.exe`，需配合 **localhost** 补丁连本地服务器。

---

## 二、各版本搭建方式对比

### v83 — Cosmic（北斗最直接的参考）
- **数据库**：装 MySQL 8+ 与 HeidiSQL，建一个名为 `cosmic` 的 schema；服务端首次启动会自动建表并填初始数据。
- **服务端**：需 **Java 21**（推荐 Amazon Corretto）+ IntelliJ IDEA；改 `config.yaml` 里的 `DB_PASS`；主类 `net.server.Server`，看到 "Cosmic is now online" 即成功。
  - 也支持 `docker compose up` 一键起；或 Maven Wrapper `./mvnw.cmd clean package` 打 fat jar 后 `launch.bat` 启动（jar 不含 WZ，需用 `wz-path` 指定）。
- **客户端**：单独仓库 `P0nk/Cosmic-client`。
- **默认管理员账号**：用户 `admin` / 密码 `admin` / PIN `0000` / PIC `000000`；支持"自动注册"（输入不存在的账号即创建）。
- **GM 技巧**：登录 GM 角色默认隐身，`@hide` 切换；`@commands` 查看全部命令。

> **北斗对比**：北斗也是 Java 21 + Maven，但用 **SpringBoot 3.2 + Flyway 自动建库 + MyBatis-Flex**，配置在 `application.yml`，REST 端口 8686、登录端口 8484。详见 CLAUDE.md。

### v83 — HeavenMS（经典老式搭建）
- **服务端用 Java 8**（早期 Java 7），NetBeans "用现有代码新建项目"，手动把 `cores/` 下的 JAR（mina-core、slf4j 等）加入 Libraries，再 Clean and Build。
- 数据库依次执行 `sql/db_database.sql`、`sql/db_drops.sql`（可选 `db_shopupdate.sql`），生成 `heavenms` schema，**手动在 accounts 表插入账号**。
- 配置 `configuration.ini` 的 IP（本机填 `localhost`）。
- WampServer 跑 MySQL，Hamachi 可选（联机用，单机不需要）。
- 网络层用 **Apache MINA**。
- **改 GM 等级**：在 characters 表手动改该角色的 gm 字段（角色需离线）。

### v0.83 — Destiny（C# 系）
- 技术栈：**C# + MoonSharp(Lua 脚本) + MySQL**，VS 2017+。
- NuGet 装 `MySql.Data 6.10.8` 与 `MoonSharp.Interpreter 2.0.0`。
- **三服分离**，按顺序启动：`WvsCenter → WvsLogin → WvsGame(s)`，每个服会引导你自动配置。

### v95.1 — Edelstein（C# / .NET，模块化）
- `dotnet build` 或用 VS/Rider；
- 资源用 **NX 格式**：下载 `Server.NX`（数据）和 `Server.Scripts`（脚本）解压；
- 运行 Standalone：复制 `appsettings.json → appsettings.Production.json`，配好 scripts/data 路径，`dotnet run`。

### v28 — Valhalla（Go 系）
- `go build` 后 `./Valhalla -type dev -config config_dev.toml` 一键起四服（dev 模式单进程，自动注册 + 2 倍倍率）。
- 仍需 MySQL；NPC 脚本用 **goja(JS)**，支持热加载。
- 生产可分进程，支持 Docker / Kubernetes，自带 Grafana 监控面板。
- 客户端需配套的 hook DLL 做 localhost + 窗口化。

### v113 — 台服（Java + Netty + Gradle）
- `gradle buildAndCopy` 编译，`Launcher.bat` 启动；
- **Java 8 编译**，网络层已升级为 **Netty**（与北斗一致）。

### v214 — Moonlight（高版本 + Docker）
- 基于 Swordie v214 源；服务端与数据库跑在 **Docker** 容器，`./start.sh` 启动（首次需几分钟生成 DAT）。
- **客户端**：推荐用 Steam 控制台 `download_depot 216150 ...` 下载 GMS v214。
- **WZ**：体积巨大不入库，需自己用 HaRepacker Resurrected dump 成 Private Server XML 放到 `Server/wz`。
- 需要填 `.env`（参考 `.env.local`）。

## 三、客户端 localhost 与 IP 修改（v83 通用要点）

私服客户端要连本地/自建服务器，需处理 localhost：
1. 安装官方客户端后，删除 `HShield`(文件夹)、`ASPLnchr.exe`、`MapleStory.exe`、`Patcher.exe`。
2. 放入 `localhost.exe`（破解过的启动器）。
3. **覆盖 WZ**：用服务端配套的（可能是定制）WZ 覆盖客户端原 WZ。
4. **改目标 IP**：若服务端不是 `localhost`，需用十六进制编辑器（如 Neo Hex Editor）打开 `localhost.exe`，搜索字符串 `127.0.0.1`，在所有出现位置改成你的 IP 后保存。
5. **兼容性**（Win8/10）：localhost.exe 属性设 Windows 7 兼容模式、640×480、以管理员运行；必要时配合 `lolwut.exe`。

> ⚠️ localhost.exe 这类破解启动器常被杀软误报为木马（因逆向手段所致）；社区资料里也多次提醒"不要用来路不明的 exe 启动服务端"（如 CMS143 的警告）。请只用可信来源。

## 四、端口转发（让外网玩家可连，v83）

- 需要开放的端口：**8484**（登录）+ **频道端口段**（如 7575 起，开 N 个频道就开 7575 ~ 7575+N）。
- 路由器里做 Port Forwarding（TCP/UDP），并在系统防火墙建入站+出站规则放行客户端程序。
- 想挂网页再转发 80 端口。

> **北斗对应**：登录端口由 `gms.service.login-port`（默认 8484）配置，Web 后台 8686；网络绑定见 `gms.service.wan-host/lan-host/localhost`。
