## B. 为何 p 版“VA 修对了”仍无效

Client_1 反汇编（文件字节）：

```
; ===== 角色装备 Tip/点击（正确）=====
0x007FEC32: 33 D2             xor edx, edx
0x007FEC34: B9 64 22 BE 00    mov ecx, BE2264   ; HitTest 表
...
0x007FEC6F: 81 F9 F4 23 BE 00 cmp ecx, BE23F4   ; 只扫到 BP50
0x007FEC75: 72 C2             jb  loop
; callers: 0x7FE4F7, 0x7FE9FC（装备栏鼠标）

; ===== 宠物装备 HitTest（p/n 误打这里）=====
0x008011FA: ... GetPetEquipFromPoint ...
0x00801214: 83 FE 30          cmp esi, 0x30
0x008013A3: 83 FA 32          cmp edx, 0x32
; 含 BP14/21/22/23/26/27/28/46 宠物特判
```

p 版把宠物循环扩到 BP51，角色 `GetBodyPartFromPoint` **从未**看到 BP51 → 无 Tip、不能选卸；宠物循环被污染 → soft。

## C. 本轮补丁（精确字节）

### C1. 角色 HitTest 循环尾（运行时写 BeiDou.exe）

| VA | 前（exe 静态） | 后（进图挂载后） |
|----|----------------|------------------|
| `0x007FEC6F` | `81 F9 F4 23 BE 00` | `81 F9 FC 23 BE 00` |

含义：表游标终点 `BE23F4→BE23FC`，多测 **index50 / BP51**。  
挂载前会校验函数头 `33 D2 B9 64 22 BE 00`，不匹配则 **拒绝写入**（防错端）。

### C2. 坐标表（运行时写 `.data`）

| 槽 | 表 | index | BP | XY |
|----|----|-------|----|----|
| 第二坠 | GetSlotXY `BE2580` + HitTest `BE2260` | 50 | 51 | `(104,134)` |
| 腰带/轮回 | 同上 | 49 | 50 | `(71,167)` |
| 勋章 | 同上 | 48 | 49 | `(5,68)` |

另：右栏 BP4/10–16 HitTest→GetSlotXY 对齐（武器悬停，沿用 j 版）。

### C3. 明确禁用 / 删除的错误做法

| 做法 | 状态 |
|------|------|
| Patch `0x801214` / `0x8013A3` | **禁用** |
| ForceDrawLoop `@7FEFB9` | **禁用** |
| Park BP22/23 GetSlotXY 到屏外或 `(46,44)` | **取消**（伤宠物绘制） |
| 改 `BE27E0`（经 PE 核对不像经典装备格表） | **本轮不再写** |

### C4. 红底（shoulders）

- `is_correct_bodypart`：`112→17|51`，`113→50`（保留）
- `IsAbleToWear`：原检查已通过的 `112` 保持返回成功（避免半截 UI 旗标导致再染红）

## F. 残留风险（如实）

1. **HitTest[50] 与 cash 表首槽同址**（`BE23F0`）：改第二坠 HT 会改 cash[0] 静态坐标；经典装备栏优先，若点开时装栏发现帽槽坐标异常再单独处理。  
2. **BP23 GetSlotXY 仍为 `(104,134)`**（与第二坠同格）：不再 park，以免宠物 soft；若空槽装饰仍叠红，再改为「仅角色绘制跳过 BP23」而不是改坐标。  
3. 补丁在 **进图后** 挂载；若未进频道就开装备栏，可能尚未生效。  
4. 未改 WZ/UI 美术（MCP 证实窄栏未变）。
