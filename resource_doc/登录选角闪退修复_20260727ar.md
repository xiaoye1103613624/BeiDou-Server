# FIX_LOGIN_CRASH_20260727ar

## 现象
选择角色后客户端闪退（`BeiDou-Client_1` 戳记仍为 `FIX_RING34_RELOG_SYNC_20260727aq`）。

## 证据
| 项 | 结果 |
|----|------|
| Client DLL | `ijl15.dll` 含 `FIX_RING34_RELOG_SYNC_20260727aq`（apply `@4E5D0C`/`@4E5DCC`→55） |
| DB char1 | `−52`=1113073，`−53`=1113075；无 `−54/−55`；无魂戒 `−112/−152` |
| Server | `PlayerLoggedinHandler` 在 `getCharInfo` 后立刻 `syncExtendedEquipSlotsToClient` |
| 同步包 | 对已穿扩展槽发 `INVENTORY_OPERATION` **remove(3)+add(0)**，equipped remove 会写 **addMovement=2** |
| 时机 | 在 `getMap().addPlayer` / CField 就绪**之前** |

## 根因
aq 客户端登录 apply 已放行 BP52–55，`getCharInfo` 的 `addInventoryInfo` 已写入 `−52/−53`。随后再发 equipped **remove+addMovement**（地图未进）→ 选角进图闪退。

不是魂戒 `migrateKeepOneOnLogin`（本角无多件魂戒），也不是未重启旧 am/an 路径（运行中 class 含 aq sync）。

## 修复
1. **去掉** `getCharInfo` 后的 `syncExtendedEquipSlotsToClient` 调用  
2. 方法改为 **no-op**；保留可选 `syncExtendedEquipSlotsAfterMap`（add-only，默认关闭）给旧 DLL A/B  
3. 重登图标依赖：**ijl15 apply-max=55 + getCharInfo**（与护肩 `−20` 同路径）

戳记：`FIX_LOGIN_CRASH_20260727ar`（服务端）

## 验证
1. 重启服务端（加载本修复）+ 完全退出客户端再开  
2. 选角色 → **不闪退**，进图成功  
3. 装备栏红标 3/4（`−52/−53`）仍有戒  
4. 再重登一次确认仍在  
5. 服务端日志不应再出现 `syncExtendedEquipSlots: chr … resent`
