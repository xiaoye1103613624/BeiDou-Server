## 未解决 → 已定位可修路径(勿再靠换 d3d8)

### 现象(文档原结论)
- **3131003**:✅ 端到端可用
- **3131056 / 3131012 / 3131007**:释放时 GR2D **D3D8 vtable[1] 空指针**(EIP=0)或卡死
- MR 有自定义 `d3d8.dll`,BD 换上会乱码 → **不要**把换 d3d8 当修复手段

### 真正可操作根因(对照 WZ,2026-08-22)
| 技能 | 原先 slim(~793KB) | 原先 cast-safe fat(~16.7MB) | 问题 |
|---|---|---|---|
| 3131003 | `shoot1`+effect0/1 stub,但 **ball 有完整 canvas+_hash + repeat=4 + delay=1200** | 无 action/e0,effect×15,ball×16+**repeat** | 模板技能 |
| 3131056 | 同结构 stub,但 **ball/0 无 _hash**(残画布) | 无 action/e0,effect×30,ball **缺 repeat**,delay=0 | 射击链不完整 → GR2D 空 vtable |
| 3131012 | 同上残 ball + shoot1/effect0 | 已 strip dragonFly/e0,ball **缺 repeat** | 同上 |
| 3131007 | `action=alert2` buff | 仍带 `alert2` | 北斗缺该动作名易崩 |

结论:**不是“v83 渲染无解”**,而是技能节点与唯一可放的 `3131003` 不一致。MR 的 d3d8 只是掩盖/旁路,BD 不能用。
