# 融合外观（武器幻化 / Fusion Anvil）

> 适用：BeiDou-Server_S9（服务端）+ BeiDou-ijl15_S9（客户端插件）+ BeiDou-Client_S9
> 现金道具：**5900000 融合外观锻造锤**（窗口商城「XY玩法」页，5 万点券）

## 1. 数据流

| 环节 | 位置 |

## 2. 协议与参考实现对齐

对齐 `F:\MXD_dev\扩展改动\融合外观`（目标态）：

- 服务端 `addItemInfo` 在 `writeInt(-1)` 之后**必须**追加 `anvilItemId`（无幻化为 0）。
  现行 ijl15 钩子在包内仍剩 ≥4 字节时总会 `Decode4`；停写会导致选角 CharInfo 错位闪退
  （见 `docs/features/char-select-crash/`）。
- 插件：`GW_ItemSlotBase::Decode` 原生解码后 `Decode4` → `nAnvilItemID@0xF9`（勿再消费旧版 71B 潜能/灵魂/星岩尾）。
- **外观广播**：`addCharEquips` 仍可用 `anvilItemId` 替换 itemId（与 CharInfo 尾字段并行）。
- 主 tip：`外观 : 皮肤名 (幻化)`；对比 tip 在「仅身上有幻化」时显示 `(无) -> 皮肤名 (幻化)`。

> 若要去掉 CharInfo 尾字段：必须先改插件钩子不再 Decode4，再停写服务端，两端同发验证。

## 3. 协议（C→S，opcode 0x4F USE_CASH_ITEM）

```
short position      // 锤子在现金背包的槽位
int   itemId        // 5900000
short skinPos       // 外观源装备槽位；-1(0xFFFF) = 还原原始外观
short basePos       // 基底装备槽位（保留属性），负数表示已穿戴
```

服务端校验：两件都必须是 `Equip`、不能同 itemId、必须同大类（`itemId / 10000` 相同）、
外观源必须在装备栏（未穿戴）。通过后 `setAnvilItemId`，删除+重发该装备并广播外观，
消耗外观源装备与锤子。

还原（`skinPos == -1`）：清除 `anvilItemId`，消耗 1 个锤子；若该装备没有外观可还原，
只提示并 return，不扣锤子。

## 4. 客户端 / 插件要点

- `UI/UIWindow.img/Synthesizing` **在 v83 客户端不存在**（已确认 Data/UI/UIWindow.img
  与 Custom.wz 均无该节点）。插件构造时若 `backgrnd` 加载失败则 `m_bFallbackDraw = 1`，
  改为**自绘窗口**：标题栏、两个槽位、确定 / 取消 / 还原三个按钮（中文用 UTF-16 码点
  转义，禁止 UTF-8 字面量直出）。
- 字体创建复用 `worldmapinfo.cpp` 已验证的 WzFont ctor 地址 `0x0046341A`（同 EXE，
  非新增 hook 地址；**未改动任何既有 hook 地址**）。
- 挂接点：`FusionAnvil::EnsurePacketHooks()` @ `LazyCompatInit`（登录前），
  `EnsureHooks()` @ `LazyCompatInit`（进图后）；tooltip hook 仍处于 soft-disable 状态
  （历史 enter 崩溃 bisect），不影响融合/还原。
- **外观源装备会被消耗**（设计如此）：左槽「外观源」融合后删除，右槽「基底」保留属性并写入 `anvilItemId`。

## 6. 已知限制

- 背包/装备栏图标仍是基底装备原图标，只有角色外观（AvatarLook）变成外观 ID。
- 交易/拍卖/雇佣商店的展示包不带外观信息，买家看到的仍是基底装备（属性正确）；查看他人详情走 `USER_INFO_EX`。
- 「还原」目前只能通过融合外观窗口的还原按钮（消耗 1 个锤子）。
- **融合会消耗外观源装备**——提示成功后「烈焰之杖」等外观源消失是预期行为，不是丢物品 bug。
